# Dex V8：硬件边界内拟合与分状态接触

支持 BONES-SEED: Skeletal Everyday Embodiment Dataset 的 SOMA Uniform BVH，以及 Ubisoft La Forge Animation Dataset（LAFAN1）原始 BVH。求解器身份 `dex_v8_per_axis_velocity`，正式版本 `V8_cpu_coupled_arms_20261105`，当前策略 `per_axis_velocity_v8_mink_arm_recovery_v2`。保持原动作时间轴，输出50Hz。

## 关节与动作

每轴相邻帧步长不超过 `min(model.json 中同名关节 velocity, 720°/s)/fps`。模型中的限值作为转换硬边界，不将其等同于已经真机测得的电机性能。手臂七轴在速度与位置边界内共同拟合人体方向、掌姿和肘轴；J6/J7保留 NASA 人体活动范围与机器人限位的交集。姿态更新直接求解带约束的稀疏二次子问题，避免先压肩部速度、再无法补回手指向。

运动学目标可能互相竞争。保持动作时长时，速度合格不保证完全复现人体。输出仍需姿态、接触及真实训练读取检查。任何轴导出为float32后超速，拒绝写成成功结果。

## 固定骨架标定

LAFAN1 原始脚趾骨相对脚踝的方向固定。先核实原骨架层级、尺寸和固定旋转，再使用官方FBX参考人体鞋底表面建立固定法向、脚跟和前掌点。GMR 的 Toe 朝向提供坐标约定；参考鞋底几何给出固定表面修正，不根据每段动作的站立姿势重算。配置记录官方资产SHA。没有站立、全程腾空、摔倒或躺卧，都不妨碍使用同一骨架定义。

SOMA保留NVIDIA发布的固定脚部点和法向；非脚部表面由官方USD的蒙皮绑定提取。LAFAN和SOMA均使用按骨骼绑定的刚性表面凸包近似，关节处的皮肤混合不是精确重建，接触更不等同于实测受力。普通mocap的缺失表面仅允许显式标注为较低可信度的几何代理，不冒充官方人体表面。

## 场景地面与接触

两个已知源配置使用其Z-up场景地面约定 `z=0`，可通过 `contact.scene_ground_override` 显式指定平面。约定值与实测地面在元数据中分开记录；不逐帧移动地面，也不把腾空脚的最低点当作地面。无场景配置的兼容mocap路径仍记录其估计方式，不能当作已知地面或完整场景复原。

站立、走路：保留平脚/脚尖/脚跟、稳定门控、中值锚点与过渡传播；支撑精修维持共同骨盆、关节边界和逐轴速度。SOMA保留NVIDIA官方5cm高度差条件。LAFAN参考鞋的前掌、脚跟取点跨度更长，不能照搬同一线性高度差并无意收紧脚底倾角；采用不小于5cm、与原18°平脚倾角一致的跨度换算。两个端点仍必须同时满足原有近地面、低速和持续时间门控；真正抬起脚跟或脚尖时仍保留相应支撑方式。

腾空：没有可信接触时不施加地面锚定，保留根部和肢体的腾空轨迹。持续静止且整机所有表面均离开已知地面仍需检查，不能用脚离地直接判断悬空。

跪地、手撑、坐卧：使用对应人体表面的接触候选，对机器人相应部位施加接触目标，并检查所有可视凸包的地面穿透。接触识别与固定骨架标定独立。

滑动、滚动：保留切向运动；滑动/滚动接触只约束法向，不锁死XYZ。身体候选不使用人体世界XY强制锚点；脚部仍保留原XYZ锚点。最终全身接触拟合在关节和逐轴速度边界内进行；小规模数值子问题可接受已验证可行但最优性预算未完成的改进步，记录次数，并由最终真实轨迹重新验收，不据求解器状态冒充输出合格。 对近重复表面约束造成的数值停滞，使用独立线性规划在原约束内做最小可行性修正，并逐行复核。表面不穿地约束为z≥0，已确认支撑脚的高度等式为z=0，二者采用相同地面定义。

单平面不包含障碍物实体或家具。缺少场景几何的抬高支撑不能被解释成已复原的真实场景。

## 产物和验收

`work/<id>/motion.pkl`：XYZW，人工回放。`work/<id>/motion.npz`：与预览 PKL 同字段布局，不能冒充训练 NPZ。`motions/<id>.npz`：WXYZ、`root_joint_lossless_v1`，供训练读取，字段转换不再次求解。

`motion.json`：源骨架/场景/几何资产、人体腕部限制、逐轴限值、手臂和全身接触求解诊断，以及自碰撞修复与导出复验记录。

`motion.diagnostics.npz`：原始人体目标、足部接触以及非脚部fixed/sliding/rolling候选。

`motion.support.json`：使用 `hybrid_cpu_v1` 脚部精修时生成，记录逐帧路由、QP 次数、停止原因与回退触发项。

`motion.pose_errors.npz`、`motion.check.json`：逐帧姿态误差、四秒局部窗口、全身穿透、脚部接触/滑移及悬空。局部窗口用于定位明显退化，不因小差异重新定义A/B。

相邻帧速度验收按 `abs(q[t+1,j]-q[t,j])*fps`，数值容差0.0001rad/s。A是运动学训练候选，B是仍需修复/回看，C是转换失败；A 还要求自碰撞检测证据完整且未发现未解决碰撞。没有控制器运行或动态可执行性认证。转换身份覆盖源码、配置、固定人体表面、标定资源、模型和数值库，拒绝直接复用旧求解缓存。

## 入口

安装 `.[convert]`，包括 SciPy、CPU OSQP、Mink 1.4.0 和 qpsolvers 4.12.0。转换不依赖Blender、USD运行时或GPU；原始FBX/USD仅用于一次性生成已冻结的表面配置。

```bash
dex-sm data check-speed /path/to/motion.pkl
dex-sm data convert --dataset bones_seed --manifest data/bones_seed/sources.jsonl --out data/bones_seed/processed_v8_constrained --workers 1
dex-sm data convert --dataset lafan1 --manifest data/lafan1/sources.jsonl --out data/lafan1/processed_v8_constrained --workers 1
dex-sm data build --records data/bones_seed/processed_v8_constrained/records --out data/bones_seed/release_v8_constrained --device cpu
```

远端全量使用桌面Data下的标准Pipeline，保留MJB编译缓存、父进程只读模型共享、独立MjData、单线程数学库、资源保留及逐动作落盘。新策略使用新数据目录；旧动作与历史报告保留，不自动改名为新结果。

## CPU 脚部轻量精修（2026-11-05）

默认 `solver.support_refinement="hybrid_cpu_v1"`。先按真实鞋面、接触和修正后的前一帧速度边界检查已有解，满足且根部修正连续时直接保留。普通帧用真实 Dex 雅可比构建15变量（骨盆XYZ与双腿）小规模QP，最多6次线性化；整鞋顶点参与检查，防止最低顶点切换造成往复。失败回退原SLSQP配方。目标函数只去掉与15变量无关的重复计算，保留常量代价，随机扰动验证代价/梯度与原式一致。轻量分支可在满足原数值容差后提前退出，因此结果不要求与旧解逐位相同。

关节角度、逐轴速度及接触XY任务不变；整鞋最低Z与支撑位置误差的最终验收容差后来统一为 1 mm（见文末支撑验收补丁），最终全身接触与导出速度检查继续执行。J6/J7、肘窝、手臂规划、接触识别及A/B评级不变。可通过自定义配置的 `support_refinement="legacy_slsqp"` 对照原精修；模块CLI接受 `--config`，不需要另留一个正式转换器。

SOMA的两段骨骼几何解用于给机器人IK提供初值，不直接输出Dex电机角。`support_geometric_seed=false`为默认：本轮两个样本上的几何初值未获得稳定额外收益，保留为显式试验开关。本实现未依赖SOMA/Pink运行时。

六组43～121帧短窗口：脚部阶段原/新耗时分别为 BONES 3.278/0.773秒、LAFAN 10.791/2.364秒、快速舞段7.917/2.805秒、脚尖支撑22.758/13.310秒、落地5.950/1.644秒、地面动作8.860/5.350秒；提速1.66～4.57倍，只代表该阶段单线程实测。572个参与帧中20帧回退，零新增约束失败，最终float32导出零超速。接触误差范数最大0.117mm，支撑滑移P95最大0.907mm/s，躯干/手指向/掌宽方向/肘轴P95变化小于0.001度。旧解更接近数值零，新解利用原逐分量0.1mm容差；不是放宽接触要求。

## 旁路计算优化与回退诊断补丁（2026-11-05）

输出新增 `*.support.json`，逐帧记录 `light_stop_reason`、`qp_status`、`qp_iterations`、`fallback_triggers`、回退前残差/最低鞋面高度、`final_feasible` 与耗时。`*.json` 的 `support_refinement_statistics` 汇总这些计数和QP setup/solve、回退时间。`*.diagnostics.npz` 增加停止原因/触发项字符串及最终可行性布尔字段，无需开启pickle。回退可同时有多个触发项，计数不能直接相加当作帧数；QP达到迭代上限也可能已有可行解，必须与最终失败分开。

## CPU求解加速补丁（2026-11-05）

实现补丁 `cpu_adaptive_arm_objective_scale_20261105`，沿用V8发布名；源码和配置指纹区分新旧输出，不能混用缓存。`solver.arm_adaptive_candidates=true`、`solver.support_qp_scaling="objective"` 为本次默认。需要对照时，设为 `false`、`"none"` 保留原候选搜索和QP数值尺度。

同一个Robot仅缓存最近姿态的FK、身体/局部点雅可比与根旋转转换；姿态改变清空雅可比缓存，返回数组独立，模型按既有只读使用约定运行。每条动作仍有独立状态。外置标准Pipeline的MJB/模型共享不重复改造。

手臂在原时间节点先求初解、前两候选与解剖中性分支；每8节点及首尾完整搜索。目标方向变化超过10度、近伸直15度内、距限位0.12rad内、最优代价较前节点超过1.25倍加0.3，均补齐原完整搜索。它们是开销调度条件，不改变物理规则。整段路径选择、逐帧拟合、平滑及逐轴限速保持。元数据按左右臂记录候选/路径/逐帧/时序/约束五阶段计时及求解次数、搜索触发原因。局部测试不能保证长动作不会漏掉未来更好的分支，仍需完整单动作回归。

脚部QP的H与梯度统一除以H对角中位数，保留任务相对权重、所有约束、变量和信赖域；OSQP容差不变，最后仍在物理单位下检查真实鞋面、接触及速度。有限精度结果允许微差。未采用变量/约束行缩放，实测该方案在脚尖窗口更慢。

本次94项测试、7组短窗口（两个数据集入口样本、快速指向/近伸直、91.5秒附近、脚尖、落地、地面）通过物理角限、导出逐轴速度及脚部/身体接触检查。单独启用缓存或自适应手臂时，四组手臂样本最终输出逐元素一致；组合脚部缩放后有微小姿态差异。具体计时与误差见本次安装回执的 `window_report`。没有重跑完整动作或全库，不能将短窗口倍率当全库倍率。

参考：[OSQP数值设置](https://osqp.org/docs/interfaces/solver_settings.html)、[更新与热启动接口](https://osqp.org/docs/interfaces/python.html)。本补丁未复用OSQP实例，也未增加最大迭代次数。


## Mink 手臂避碰补丁（2026-11-05）

补丁身份 `cpu_mink_arm_collision_20261105`。实际调用 [Mink CollisionAvoidanceLimit](https://github.com/kevinzakka/mink/blob/main/src/mink/limits/collision_avoidance_limit.py)，不是只参考公式。完整全身接触处理后增加自碰撞扫描，再对碰撞附近的小窗口修复。骨盆、腰、腿保持原数据；只调整碰撞涉及的手臂。没有碰撞的动作逐值保留。

覆盖 240 对碰撞几何：双臂各自与躯干、骨盆、髋部、头部，以及左右臂之间。包含前臂、腕部及手部；当前不覆盖同一条手臂内部、手臂与膝盖/脚踝等其余组合。Mink 排除同刚体、焊接和直接父子连接。仅在独立模型副本中修改碰撞掩码，正式 XML、共享批处理模型和训练模型不变。

Mink 对已经穿入的姿态主要限制继续靠近，不能自动将其推出；本补丁补充有符号距离的恢复位移要求，并用实际更新后的几何重新验收。求解器返回成功不代表非线性碰撞已解决。保留原手指向、掌姿、前臂、肘窝任务和 J6/J7 边界，增加手臂表面不穿地约束，并逐轴约束相邻帧和窗口接缝速度。
